# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

keith's friend club — an ephemeral video chat app on the AT Protocol (Bluesky). Users log in with Bluesky OAuth, record a 2-second webcam video, write a message, and share it. Messages are stored on the user's PDS (Personal Data Server); the server's SQLite is only a cache.

## Commands

```bash
npm run dev              # node --watch with .env loaded (port 3891)
npm run start            # production server
npm run typecheck        # tsc, no emit
npm run keygen           # print OAUTH_PRIVATE_KEY and COOKIE_SECRET for .env
npm run lexicons:build   # regenerate src/lexicons from lexicons/
npm run lexicons:update  # re-fetch installed lexicons, then rebuild
```

No build step. Node 24+ runs the TypeScript directly (type stripping), so relative imports need explicit `.ts` extensions and code must be erasable syntax only (no enums, namespaces, or parameter properties). `bun install` is fine for installing packages; the runtime is Node.

**Prerequisites:** Node 24+, ffmpeg + ffprobe. OAuth needs a public https URL (ngrok/cloudflare tunnel for local dev) and `OAUTH_PRIVATE_KEY` + `COOKIE_SECRET` in `.env`.

## Architecture

### PDS-First Data Flow

This is the most important thing to understand. The server is NOT the source of truth:

1. `POST /api/message` uploads video blob + creates `is.keith.fc.message` record on the **user's PDS**
2. Jetstream v2 detects the new record and sends it back to the server
3. Server validates it with the generated lexicon schema, saves to SQLite cache, and broadcasts via WebSocket

Deleting works the same way — delete from PDS first, Jetstream notifies, server removes from cache. Cached messages are keyed by AT-URI.

### Key Components

- **Routes** (`src/server/routes/`) — `api.ts` (feed, messages, CRUD), `oauth.ts` (metadata, JWKS, login/callback/logout), `pages.ts` (server-rendered HTML), `static.ts` (`/public/*` with MIME types)
- **OAuth** (`src/server/lib/oauth-client.ts`) — confidential client (`private_key_jwt`, ES256 key from env). State and sessions persist in SQLite. `sessions.ts` restores a session from the signed `fc_session` cookie, which holds only the DID
- **Identity** (`src/server/lib/identity.ts`) — `@atproto/identity` resolver for did:plc and did:web, verifies handles both ways
- **Jetstream client** (`src/server/lib/jetstream.ts`) — v2 endpoint (`/xrpc/network.bsky.jetstream.subscribeEvents`), resumes from a cursor saved in the `kv` table
- **WebSocket** (`src/server/websocket.ts`) — read-only broadcast to clients; registered on the root app because plugin-level `.ws()` doesn't get the Node adapter
- **Storage** (`src/db/`) — `database.ts` owns the shared `node:sqlite` connection and all tables; message cache uses an adapter interface (SQLite default, JSON optional)
- **Expiration cleanup** (`src/server/lib/expiration-cleanup.ts`) — every minute, restores each author's stored session and deletes expired records from their PDS
- **Lexicons** — schemas in `lexicons/` (ours + installed Bluesky ones pinned in `lexicons.json`); `src/lexicons/` is generated by `lex build` and committed. Use `Client` from `@atproto/lex` with these schemas instead of raw XRPC calls

### Frontend

Plain custom elements in `src/public/js/components/` (`fc-camera`, `fc-composer`, `fc-feed`, `fc-message`, `fc-my-messages`), light DOM, loaded as native ES modules from `app.js`. Pages are server-rendered in `pages.ts` with the login state baked in (`body[data-auth]`), so they work before JS loads. Asset URLs carry `?v=<server start time>`.

### Custom ATProto Lexicon

`is.keith.fc.message` in `lexicons/is/keith/fc/message.json` — text (255 UTF-8 **bytes** max, so emoji count as several), video blob (mp4, 10MB max), optional bluesky cross-post URI, optional expiration datetime.

## Conventions

- **ABOUTME headers:** Server-side TS files use 2-line `// ABOUTME:` comments at the top (greppable).
- **No test suite** currently exists.
- **CSS:** Single file at `src/public/css/main.css`. GT Maru (local fonts) with keith.is's layout language: full-bleed pink/butter bands, system-mono labels, thick black borders, pastel cards, pink period on headings. Colors are tokens on `:root` with a dark-mode override.
- **HTML:** Template literals in `src/server/routes/pages.ts`, returned as explicit `Response` objects. Escape anything user-controlled with `escapeHtml`.

## Environment Variables

- `OAUTH_PRIVATE_KEY` — ES256 private JWK (required)
- `COOKIE_SECRET` — cookie signing secret (required)
- `BASE_URL` — public https origin for OAuth (auto-detected from headers if not set)
- `PORT` — server port (default: 3891)
- `STORAGE_ADAPTER` — `sqlite` (default) or `json` for the message cache
- `DATA_DIR` — path to data directory (default: `data`); must persist across deploys for sessions to survive

## Gotchas

- Bun can't run this: `@atproto`'s SSRF-protected fetch requires Node's bundled undici
- Elysia on the Node adapter: `set.headers` from async handlers and `redirect()` with a relative path don't work. Return a `Response` directly
- `@elysiajs/static` sends no Content-Type on Node, which is why `static.ts` exists
- SQLite prunes to 20 messages, except messages still waiting to expire; the "last 20" limit is fundamental to the design
- Video conversion shells out to ffmpeg/ffprobe via `execFile`
